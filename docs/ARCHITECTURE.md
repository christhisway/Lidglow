# Lidglow architecture

How Lidglow behaves and why, what each source file does, and what to check by hand after a change. It's written for anyone working on the code, people and coding agents alike. The code in `Sources/Lidglow/` is the source of truth, so update this file when behavior changes. For building, the project layout, and how to propose a change, see [CONTRIBUTING.md](CONTRIBUTING.md). For releases, see [RELEASE.md](RELEASE.md).

## Current behavior

- Lidglow starts in the menu bar and opens its controls only when the icon is clicked. The panel anchors below the status item, clamps to the active display’s visible frame, and grows or shrinks smoothly from its top edge when controls appear or disappear. `GlowPanel` reports its natural height through `onGeometryChange` in the same layout pass, and `positionPanel` animates the window over the same 0.22 s as the SwiftUI fade, or without animation when Reduce Motion is on. With Reduce Motion the resize waits until SwiftUI's update finishes (coalesced to the latest height), because resizing the window inside that pass re-entered SwiftUI and left the panel the wrong height. The content is pinned to the top, both in SwiftUI and in a flipped container view, and the hosting view is kept as tall as the panel can get so SwiftUI never centers content that outgrows it. Only the bottom edge moves. It never scrolls: it's always sized to its content, and capped at the visible frame. It closes on Escape and on a click outside it. Touches on a touchscreen outside the panel reach no event monitor and don't change focus, so on macOS 27 the status item's `expandedInterfaceDelegate` lets the menu bar track the panel like a menu, and the menu bar ends the session (closing the panel) on an outside touch. Tapping the icon while the panel is open ends the session and begins a new one about 75 ms later, so a session that begins within 0.25 s of a close is cancelled. The menu bar ignores mouse clicks on the icon during a session, so the monitors close the panel on the mouse-up of a press that started while it was open. The context menu detaches the delegate while it's open, or the click would also open the panel. Control-clicking or right-clicking the icon opens a context menu with Open Settings… and Quit Lidglow. A gear in the panel header, left of the switch, and ⌘, while the panel is focused also open Settings. The Settings window has General (Open at Login), Music, Agents, and About sections. It closes with ⌘W.
- A switch in the panel's top-right corner turns Lidglow on or off. Off returns control to macOS (build 1's System mode, which migrates to the switch being off) and is the first-launch default. Modes are Standard, Breathe, and Music. Standard holds a fixed brightness, and zero brightness turns the logo off (this replaced build 1's separate Off and Steady modes, which migrate to Standard). Breathe has Slow (8 s), Normal (5 s, the default), and Fast (3 s) speeds. Changing speed keeps the current point in the breath. Each mode has its own brightness (`brightness.Standard`, `brightness.Breathe`, `brightness.Music`, seeded once from build 1's shared `brightness`), and the panel's slider shows the selected mode's. Only Standard can go to zero; Breathe and Music have a 5% floor (`GlowModel.minimumBrightness`), so an automatic switch to Music is never dark. The switch, selected mode, per-mode brightness, Breathe speed, Focus preset, sensitivity, idle glow, Music app settings, automatic switching, and the Music silence timeout persist.
- While the battery charges, every mode breathes, at Breathe's brightness and speed, except Music while music is playing. Music with nothing playing breathes until playback starts, and keeps reading its input every tick so the music takes over right away. Plugged in with a full battery isn't charging, so the selected mode shows as usual. Charging is `kIOPSIsChargingKey` on the internal battery, and `PowerSource` hears changes through `IOPSNotificationCreateRunLoopSource`, with no polling, only while the switch is on. Charging also keeps the logo glowing with the lid closed, which happens only while the Mac stays awake, such as on an external display. Closing the lid hands the logo back to macOS (which turns it off) only while the battery isn't charging, and unplugging or the battery filling with the lid closed hands it back on the next tick. The glow loop reads the lid state every 0.35 s and passes it to `LidLogo`, so fades to dark with the lid closed don't relight the keyboard backlight. Lock and sleep still hand the logo back to macOS, and an agent pulse still plays over the breath. The panel shows the selected mode, with the status Breathing while charging.
- Music uses a private Core Audio process tap to meter playback, and detects transients per band. By default the tap includes only Spotify and Apple Music (`CATapDescription(monoMixdownOfProcesses:)`, matching each Core Audio process's bundle ID, including helpers such as `com.google.Chrome.helper`). Settings → Music has a Listen to picker: Chosen apps (the default; the checklist opens in a sheet from Choose…), All apps, or Microphone. With selected apps, `SystemMusic` listens for `kAudioHardwarePropertyProcessObjectList` changes, with no polling, and keeps no tap while none of them has audio open. The Focus preset picks the bands. Bass (the default), Mids, and Treble each use one narrow band with 24 dB/octave Butterworth filters: 40–120 Hz, 300 Hz–3 kHz, and above 6 kHz. A hit counts only when that band carries at least 15% (fully at 50%) of the whole mix's onset energy, so leaks from other instruments don't flash the logo. Full is the original wide bass, drum, and treble detector. Microphone, off by default, asks for access when chosen (`GlowModel.selectMusicSource`) and opens the default input through `AVAudioEngine` only while Music runs, rebuilding on `AVAudioEngineConfigurationChange`. Both inputs feed the same `BeatMeter` and lock-free level hand-off. Lidglow stores no recordings, and its only network access is Settings → About → Check for Updates.
- Settings → Music → Automatically switch to Music (off by default, shown with Chosen apps and All apps) selects Music when a chosen app, or with All apps any app, starts playing, through `select`, like a mode picked by hand. `PlaybackWatcher` reads `kAudioProcessPropertyIsRunning` (whether the process has audio running; `IsRunningOutput` never notifies listeners on macOS 27, so it only worked at launch) on the same matched process objects as the tap (`SystemMusic.processes(matching:)`), with listeners on each process and on the process list, so it needs no tap and never polls. With All apps (`bundleIDs` nil) it watches every process that plays for an app (`SystemMusic.isAppAudio`): any third-party process, any regular Apple app (`NSRunningApplication.activationPolicy == .regular`), and WebKit's media helpers. It leaves out Lidglow, whose own tap runs audio input while Music is on, and macOS's system processes, such as `systemsoundserverd` (alerts), `com.apple.MediaRemoteUIService` (volume-change feedback), Control Center, Siri, and `avconferenced` (call audio). Processes without a reverse-DNS bundle ID are system daemons and are left out too. The All apps tap uses the same rule: it's a global tap that excludes those system processes (`CATapDescription(monoGlobalTapButExcludeProcesses:)`), rebuilt from the process list listener when that set changes, so system sounds never reach the glow either. It acts only when playback starts, so a mode picked by hand while music plays stays until playback stops and starts again. Playback stopping switches back only when the timeout below is set to Automatically. A player that keeps its audio running while paused gives no new start when it resumes, so it won't switch in again until the stream closes.
- Music switches back to the mode selected before it (saved as `modeBeforeMusic`, Standard if there's none) after a stretch of silence: Settings → Music → Switch back after silence, 5, 10 (the default), 15, 30, or 60 s, or Never (`MusicTimeout`). Automatically instead switches back when `PlaybackWatcher` reports that every watched app stopped, about 2 s after a pause, and the watcher runs for it even with automatic switching into Music off. Microphone has no app stream to follow, so there it falls back to 10 s of silence (`GlowModel.silenceLimit`), and Settings says so. Silence means `music.level` stays at or below `SystemMusic.soundThreshold`, whatever the source, including while Music waits for a chosen app to open audio. The glow loop keeps the clock (`musicHeard`), so there's no extra timer, and every pause clears it, so time locked, asleep, or with the lid closed doesn't count. Leaving goes through `select`, like a mode picked by hand. An audio error keeps Music on screen so the error stays visible.
- Agent alerts (Settings → Agents → Pulse when an agent needs you, off by default) pulse the logo when a coding agent is waiting for you. It's a toggle, not a fourth mode: the pulse plays over whichever mode is selected and then hands the logo back to it. Agents reach Lidglow through hooks that run `pgrep -qx Lidglow && open -g 'lidglow://agent/<signal>?agent=<name>' || true`, so nothing listens on the network, an agent never launches Lidglow, and the hook never reports an error. `LidglowApp.application(_:open:)` receives the link and `AgentRequest` accepts exactly one path component (`attention`, `done`, or `clear`), an `agent` query item (`claude-code` or `codex`), and optionally `app` (must look like a bundle ID) and `pid` (a number above 1) after it, each at most once and empty counting as none, with no user, port, fragment, or other query items. Anything else is dropped without logging its contents, so another app opening a `lidglow://` link can at worst make the logo pulse. Claude Code's hooks go in `~/.claude/settings.json`: `Notification` (permission prompts, idle prompts, and questions) sends `attention`, `Stop` sends `done`, and `UserPromptSubmit` and `PostToolUse` (async) send `clear`. Codex's go in `~/.codex/hooks.json` with `PermissionRequest` in place of `Notification`, and need trusting through `/hooks`. Each agent's Set Up… sheet shows and copies the exact hooks. Lidglow never edits another app's config. Signals are acted on only while Agent alerts and that agent's toggle are on, and `attention` and `done` are ignored while the panel is open. They also need the panel's switch on, unless Pulse even when Lidglow is off is on (off by default). Then a pulse while the switch is off starts the glow loop just for the pulse (`shouldRun`), and when the pulse ends `pulseEnded` stops the loop, which hands the logo back to macOS, so nothing runs between pulses. Turning the switch off, or turning that option off while the switch is off, clears the pulse. `done` pulses only with Also pulse when an agent finishes (on by default). The pulse (`AgentPulse`) is a double flash every 2 s at its own Pulse brightness (100% by default, 5% floor), so it shows even with Standard at zero. With Reduce Motion (read when the pulse starts) it's one longer flash with slower fades. Several agents share one pulse until all are cleared, and the status names the agent or counts them. `attention` and `done` hooks append `&app=$__CFBundleIdentifier&pid=$PPID`. `pid` is the agent's own process (the hook shell's parent), and `AgentClickWatcher.hostApp(ofProcess:)` walks up its parents (`sysctl` `KERN_PROC_PID`) to the first regular app other than Lidglow: the Claude app for Claude Code, ChatGPT (`com.openai.codex`) for Codex's bundled CLI, or Terminal or VS Code for a shell. `app` is the fallback when that walk finds no app, for example under tmux. macOS sets `__CFBundleIdentifier` to the bundle ID of the app that launched a process, but it's undocumented and Codex under the ChatGPT app runs without it, which is why the walk comes first. With Stop pulsing when I click in the agent's app (on by default), `AgentClickWatcher` installs a global mouse-down monitor only while a waiting agent named its app, and for each click reads the owner of the topmost window at the pointer (`NSWindow.windowNumber(at:belowWindowWithWindowNumber:)`, then the owner PID from `CGWindowListCopyWindowInfo`). A click in that app's windows clears every agent waiting in it, unless its signal arrived within the last second. Neither step needs Accessibility or Screen Recording permission, and nothing else about the window or click is read. It works whether or not the app is in front, but can't tell the app's windows or tabs apart. The pulse stops when every waiting agent sends `clear`, when you click in its app, when the panel opens, when Agent alerts, the agent, or the switch is turned off, or after Stop pulsing after (15 minutes by default, counted from the latest signal, or Never). It runs in the glow loop at Breathe's 30 Hz only while something is waiting, with no timer of its own, and drives the logo through `LidLogo` like any mode, so lock, sleep, lid close, the switch, quit, and interference detection behave as usual mid-pulse. Waiting agents aren't saved across a relaunch. When it ends, Music restarts its silence clock so the pulse doesn't count as silence.
- Idle glow sets a base between hits and tracks, capped at 90% of the chosen peak so beats can still brighten the logo. The preview and physical LED both glow white.
- Each opening of the panel replays the laptop animation, then switches to a 2D logo that follows the live brightness. Reduce Motion goes directly to the 2D view.
- Lidglow steps aside for any other app that controls the logo. While it holds the logo, `LidLogo` compares each level reading with the way its last command should move the logo (up, down, or held still) over windows of at least 0.3 s, and reads the backlight mode once a second. Four unexplained moves within 20 seconds, or the backlight switched off, make it restore the logo and ask the user to quit the other app. `OtherLogoApps` also recognizes some logo apps by bundle ID (currently `co.supershort.backglow`, `app.logolight.LogoLight`, and `app.lidlight.Lidlight`): while one is running, Lidglow doesn't take control, names it in the panel, and takes over when it quits.
- Music and logo control pause on session lock, sleep, or lid closure, except lid closure while the battery charges. Normal quit restores macOS control, and so do `SIGTERM`, `SIGINT`, and `SIGHUP` (`kill`, Ctrl-C, or closing Terminal), which go through a normal quit. While Lidglow holds the logo, macOS's original backlight mode is saved in `UserDefaults` (`logoHeldOriginalMode`) and cleared by every restore. If it's still set at launch, after a crash, a force quit, or `kill -9`, `LidLogo.recoverAfterUnexpectedExit()` runs the restore sequence before anything reads the logo's state. Unsupported hardware uses the preview. So does a missing or changed CoreBrightness interface (`LogoBridge.serviceAvailable` is NO), with the status “Preview only · Lid logo service unavailable”.

## Source map

| File | Role |
| --- | --- |
| `App/Main.swift` | Entry point; starts the accessory (menu-bar) app, or only unregisters the login item for the uninstaller |
| `App/Log.swift` | `Logger` categories for local diagnostics (hardware, audio, update checks, and agent alerts, no audio data) |
| `App/Updater.swift` | Check for Updates: runs the bundled `install.sh --update` only on a click, reads its exit code (staged, up to date, no stable release, or failed), and quits normally so the installer can replace the app |
| `App/LidglowApp.swift` | Application delegate: status item and its context menu, panel window, positioning, event monitors, Settings window, and `lidglow://` agent links |
| `Glow/GlowMode.swift` | The modes and their icons, the Breathe speeds, and the Music silence timeouts |
| `Glow/GlowModel.swift` | Mode and settings state, tick loop, session lifecycle, automatic switching into and out of Music, breathing while charging, and the agent alert pulse |
| `Glow/AgentClickWatcher.swift` | While an agent waits on a known app, watches mouse clicks and reports which app owns the window under each one |
| `Glow/AgentAlert.swift` | Supported coding agents and their hook snippets, strict parsing of `lidglow://agent/…` links, the alert timeouts, and the pulse pattern |
| `UI/GlowPanel.swift` | SwiftUI glow controls |
| `UI/GlassStyle.swift` | Shared Liquid Glass surfaces and the glass mode selector |
| `UI/LaptopPreview.swift` | SceneKit intro and live logo close-up |
| `UI/LaptopChassis.swift` | Laptop geometry and materials |
| `UI/MenuPanel.swift` | Borderless key-capable panel and its glass backdrop, clipped to its rounded shape so the window shadow follows the corners |
| `UI/SettingsWindow.swift` | The Settings window with its General (Open at Login), Music (source picker and app sheet), and About (version, Check for Updates, links) sections, built on open and released on close |
| `UI/AgentSettings.swift` | Settings → Agents: the Agent alerts toggle, per-agent toggles, pulse options, and each agent's Set Up… sheet with the hooks to copy |
| `Audio/SystemMusic.swift` | Music sources: Core Audio tap lifecycle, per-app process matching, the process list listener, and microphone input |
| `Audio/PlaybackWatcher.swift` | Whether a chosen app is playing, from Core Audio's per-process running state, for switching to Music automatically |
| `Audio/BeatMeter.swift` | Band transient detection and the Focus (EQ) presets |
| `Hardware/LidLogo.swift` | Logo brightness transitions, original state tracking, restoration, recovery after an unexpected exit, and detection of other apps changing the logo |
| `Hardware/PowerSource.swift` | Whether the internal battery is charging, from IOKit's power source info and its change notification |
| `Hardware/OtherLogoApps.swift` | Recognizes some other logo apps by bundle ID through launch and quit notifications |
| `Hardware/LaptopFinish.swift` | Automatic laptop finish detection |
| `Hardware/LogoBridge.h`, `.m` | IOKit hardware detection and dynamically loaded CoreBrightness calls, with type checks and exception guards so a changed interface reads as unavailable |
| `Resources/Info.plist` | Version, bundle ID, menu-bar activation, deployment target, the `lidglow` URL scheme for agent signals, and audio and microphone permission text |
| `Resources/Lidglow.entitlements` | Microphone (audio input) entitlement, applied when `build.sh` signs with a Developer ID identity and the hardened runtime |

Paths are relative to `Sources/Lidglow/`. Outside it, `Scripts/build.sh` builds and signs the app, `Scripts/package.sh` makes the release zip and its SHA-256, `Scripts/install.sh` is the Terminal installer and updater (`build.sh` also copies it into the app's `Contents/Resources`, where `App/Updater.swift` runs it with `--update`), `Scripts/uninstall.sh` removes the app, its login item, and its settings (it runs `Lidglow --unregister-login-item`, handled in `App/Main.swift`), `docs/RELEASE.md` is the release checklist, `.github/workflows/release.yml` is the hand-started Release workflow that builds from `main`, signs with the `Lidglow Self-Signed` identity when its repository secrets are set (ad hoc otherwise), and creates the GitHub Release, and `Scripts/test.sh` runs `Tests/BeatMeterTests/BeatMeterCheck.swift` (synthetic checks for kick, snare, hi-hat, and guitar-note response, steady audio, and silence, for every Focus preset).

## Build and verify

Run `Scripts/build.sh` from the repository root. It writes `build/Lidglow.app`. Run `Scripts/test.sh` for the beat check, which covers 44.1, 48, and 96 kHz. See [CONTRIBUTING.md](CONTRIBUTING.md) for compiler setup and Developer ID signing. No package manager, external assets, or credentials are needed for local builds. Bump both version fields in `Resources/Info.plist` for a release and keep the bundle ID stable for an in-place update. `CFBundleVersion` is a whole number that goes up by one every release. `LidglowReleaseLabel` ("Beta") is shown after the version in Settings → About; remove it for a stable release. The Release workflow sets it to the beta number from the tag (for example "Beta 1") in the release build only, without committing. Build 1 was tagged `v1.0` before the beta numbering, so the beta starts at 0.9.0 (build 2) and 1.0 is kept for the first stable release.

For changes, quit other logo utilities and older Lidglow copies before testing. Launch from Finder and confirm that the menu panel opens below the icon with its controls fully visible. Test Music with playback and silence, toggle Idle glow, and check restoration when the switch is turned off and on quit. A Mac without a controllable logo can exercise the interface and audio preview.

For breathing while charging, plug in with the battery below full and check that Standard (also at zero) breathes at Breathe's brightness, that Music breathes during silence and follows the music as soon as it plays, and that unplugging, or the battery reaching full, returns to the mode. With an external display keeping the Mac awake, closing the lid while charging should keep the logo breathing on the closed lid, without lighting the keyboard backlight. Unplugging, or the battery reaching full, with the lid closed should turn the logo off, and so should closing the lid with a full battery. Lock and sleep should hand the logo back to macOS.

For agent alerts, turn on Settings → Agents and run `open -g 'lidglow://agent/attention?agent=claude-code'` in Terminal. The logo should double-pulse in every mode, including Standard at zero, then return to the mode after `open -g 'lidglow://agent/clear?agent=claude-code'`, on opening the panel, and after the timeout. Lock, sleep, close the lid, turn the switch off, and quit mid-pulse, and check that the logo goes back to macOS each time. With Pulse even when Lidglow is off on and the switch off, check that a pulse takes the logo and that it goes back to macOS when the pulse clears or times out, and after a lock, sleep, lid close, or quit mid-pulse. Then paste each agent's hooks and check that a permission prompt pulses the logo and approving it clears the pulse. With the pulse on, clicking in the agent's app should stop it, whether or not that app was in front, and clicking in other apps shouldn't. Links with an unknown signal or agent should do nothing. The pulse's fade times are starting points to tune on hardware.

For Check for Updates, the installer's `--update` mode can be tested without a published release by pointing `LIDGLOW_RELEASE_URL` at a folder holding a `Lidglow.zip` and its `.sha256` (the app passes that variable through). With a newer build in that folder, the click should quit Lidglow, return the logo to macOS, replace the app, and reopen it. With the same build it should say Lidglow is up to date and change nothing.

## Compatibility and distribution

The minimum is macOS 27, because every MacBook Pro with a light-up logo ships with it. It's set in `Resources/Info.plist` (`LSMinimumSystemVersion`), the `-target` in `Scripts/build.sh` and `Scripts/test.sh`, and `minimum_macos` in `Scripts/install.sh`, so keep them in step. With that floor, the panel always uses the system Liquid Glass (`GlassStyle.swift`, `MenuPanel.swift`) and needs no material fallback. Letting older macOS open an inert, unsupported panel is tracked post-beta in #61. Logo control uses a private CoreBrightness interface and may need adjustment after macOS updates. Keep hardware detection and restoration intact when changing that path. Core Audio capture uses the public process tap API and needs per-app system audio permission.

Lidglow is licensed GPL-3.0-or-later (`LICENSE`, copied into each release zip by `Scripts/package.sh`). Every source file starts with an `SPDX-License-Identifier` line, contributions need a DCO sign-off (`docs/CONTRIBUTING.md`), and security reports go through private advisories (`docs/SECURITY.md`). Settings → About links to the license. Releases are arm64 and unnotarized on purpose (no paid Developer ID). They're installed with `Scripts/install.sh`, which downloads with `curl` so no quarantine attribute is set, and verifies the published SHA-256. Releases are signed ad hoc for now, so macOS asks for the audio permission again after each update. Signing with a self-signed `Lidglow Self-Signed` identity (`LIDGLOW_SIGN_IDENTITY`) would keep it across updates; the Release workflow uses one automatically once it's added to repository secrets (post-beta, #69). The workflow always stops at a draft because only admins may create `v*` tags. Betas are marked as pre-releases, which `releases/latest` skips, so they're installed by name (`install.sh v0.9.0-beta.1`). Open at Login uses `SMAppService.mainApp`. The release steps are in [RELEASE.md](RELEASE.md), and signing with a Developer ID instead is covered in [CONTRIBUTING.md](CONTRIBUTING.md).
